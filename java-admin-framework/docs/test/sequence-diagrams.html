SD-01 登录鉴权链路（成功路径）

覆盖 AUTH-01 / AUTH-03 / AUTH-07 等用例。Client → AuthController → AuthService，顺序经过验证码、用户查询、口令匹配、权限装配、令牌签发、在线会话登记与审计落库。

SD-02 数据权限切面（修复后切点）

覆盖「用户/部门/待办/流程」等模块此前集体报错的关键路径。切面以 @Order(HIGHEST_PRECEDENCE) 最外层包裹，用单点 @annotation + AnnotationUtils.findAnnotation 手动解析 @DataScope（方法级与类级均命中），写入 DataScopeContext 后 proceed，finally 清除，避免 OR 组合绑定切点导致的参数绑定异常。

SD-03 系统参数读写（缓存一致）

覆盖 CFG-01~07 用例。读路径命中内存缓存直接返回，未命中回源 sys_config 并回填；写路径（create/update/delete）在落库同时同步失效/回填缓存，保证多次读取不重复查库且及时反映变更。注意 ExportController 的 /download 返回 byte[] 文件流（非 Result 包络），本图聚焦参数 CRUD。

SD-04 工作流任务认领 / 审批

覆盖 WF-01~05 用例。认领天然幂等（不强制 Idempotency-Key）；审批/转办强制 Idempotency-Key（@Idempotent requireKey=true）。审批前校验：task 不存在→404；assignee≠当前用户→403(FORBIDDEN)；任务被他人认领→409(CONFLICT)；已是自己认领→幂等成功。

SD-05 实时推送管理（会话查询 / 广播 / 定向推送）

补齐 realtime 模块缺失的 REST 入口。Client → RealtimeController → RealtimeAdminService，读取 RealtimeSessionManager 在线会话态或经 RealtimePushService 触发广播/定向推送，最终触达 WebSocket 会话。离线用户本次不推送，由前端 REST 拉取兜底。

SD-06 Kafka 消费监控与死信补偿（状态查询 / 重试 / 丢弃）

补齐 kafka 模块缺失的运维入口。Client → KafkaMonitorController → KafkaMonitorService，经 ObjectProvider 惰性获取 OrderedKafkaConsumer（未启用消费容器时返回 enabled=false 安全降级）；读取内存运行指标/死信列表，或经 retry/discard 清除位点失败计数与版本表占位以补偿毒消息。

SD-07 可观测性管理与 span 回溯（最近 span / 按 traceId / 摘要 / 指标快照）

补齐 observability 模块缺失的管理入口。请求级 span 由 OtlpTracingFilter 采集，经 List<SpanExporter> 分发给两个正交 sink：本地留存记录器（SpanRecorder，有界环形缓冲，默认开启）与 OTLP Collector 导出器（默认关闭）；管理侧 Client → ObservabilityController → ObservabilityService 按 traceId 回溯、查看双链路摘要与 Micrometer 指标快照。

SD-08 N+1 查询探测与疑似事件留存（疑似列表 / 运行态 / 清空）

补齐 N+1 探测「只写不读」的缺口。jOOQ 执行链路上 NPlusOneListener 借 probe 的线程级同构 SQL 计数，越阈值即打告警并向有界留存（NPlusOneSuspectRegistry，默认 200 条、超出淘汰最旧）登记事件；管理侧 Client → NPlusOneController → NPlusOneService 倒序查询疑似事件、查看探测运行态、清空留存。JooqConfig 与 DataSourceConfig 双路装配共用同一 probe 与留存组件。

SD-09 幂等记录管理（分页查询 / 统计摘要 / 清理过期）

补齐 M2 幂等模块「只写不查」的缺口。记录由 IdempotencyService 在请求链路写入（acquire/markSuccess/markFailed/release，均 REQUIRES_NEW 独立事务），管理侧 Client → IdempotencyRecordController → IdempotencyRecordService 提供分页查询、统计摘要与手动清理三条只读/受控写入口；查询条件经 IdempotencyRecordRules 归一（容错 posture：非法筛选值忽略），数据经 JooqWriters 访问 SYS_IDEMPOTENCY_RECORD；清理委托 IdempotencyService.purgeExpired()，与 IdempotencyCleanupJob 周期任务同口径。

SD-10 告警收件箱管理（列表 / 汇总 / 清空）

告警由 Alertmanager 经 POST /api/monitoring/alerts/webhook 写入内存收件箱（机器向、令牌鉴权）；本图为人向管理面 Client → AlertInboxController → AlertInboxService（/api/monitoring/alerts/inbox，RBAC system:monitor:read）。读取走快照副本：capacity() 定上限 → AlertInboxRules.normalizeLimit 钳制 → inbox() 取副本 → filter 归一筛选 → 截断映射为 AlertInboxItemView；汇总经 summarize 产出 severity 分布（含 unknown 桶保证守恒）；清空委托 clearInbox() 整体丢弃窗口。
